0 · Architecture & conventions

The codebase is split into three decoupled layers. The solver layer (src/solver/, plus the pure modules src/idmt.ts, src/arcFlash.ts, src/protection/) contains no React and no UI imports. The store (src/store.ts, Zustand) holds project state and dispatches every run. The UI layer imports from the solver only through store getters/actions.

Per-unit system

All electrical quantities are normalised to a common base_mva (default 100 MVA) and each bus's base kV. Impedances are converted to per-unit on the system base so that networks spanning multiple voltage levels combine correctly. Per-unit base impedance Zbase = kV² / MVAbase.

Complex arithmetic

A small complex-number library underpins every solver. Admittances, impedances and the Y-bus are complex; load flow and short circuit both operate on rectangular complex quantities.

Implementing functions

  • solver/math.ts — C, cAdd, cSub, cMul, cDiv, cConj, cAbs, cArg, cFromPolar, cInv (complex algebra); solveLinear (Gaussian elimination, partial pivoting); invertComplexMatrix (complex matrix inversion).

1 · Numerical foundation solver/math.ts

Purpose. Provide the linear-algebra primitives the iterative solvers rely on: solving the Newton–Raphson correction system and inverting the Y-bus for the short-circuit impedance matrix.

Method

solveLinear(A, b) solves A·x = b by Gaussian elimination with partial pivoting (largest-magnitude pivot per column). A pivot magnitude below 1e-14 raises a "singular matrix" error, which the load-flow path converts into a user-facing message. invertComplexMatrix performs the same on the augmented complex system to form the bus impedance matrix Z = Y⁻¹.

Limitation. The pivot tolerance is absolute (1e-14). For very stiff or badly scaled networks a relative tolerance (scaled to the largest matrix element) would be more robust.

2 · Network model — topology builder solver/network.ts

Purpose. Translate the drawn single-line diagram (components + connections) into a solver-ready model of buses, branches, sources, motors and loads.

Method — terminal-level union-find

Every component terminal is a node in a union-find structure. Two terminals share one electrical bus if joined by any chain of wires, closed switches, intact fuses or busbars (these are "transparent"). Cables and transformers separate buses (they carry real impedance). Each equivalence class becomes a BusModel:

  • A class containing a real busbar takes that busbar's label and nominal kV.
  • Otherwise it is a synthetic bus, auto-named after the components on it (rendered as a cyan dot on the canvas).

Base-kV propagation: starting from the slack bus, base voltage is carried through cables (unchanged) and through transformers (scaled by the turns ratio), so every reachable bus gets a base kV. Orphan buses (unreachable through branches — e.g. an opened breaker isolating a section) are pruned and all indices re-mapped so the solver never sees a singular system.

Implementing functions

  • solver/network.ts — buildNetwork(project, options?) → NetworkModel (buses, branches, sources, motors, loads, slack index). buildYBus(net) assembles the complex nodal admittance matrix. effectiveStartingCurrentRatio(method, lrc) for motor starting.
  • store.ts — getSyntheticBuses(), getComponentKv() expose derived bus data to the UI without breaking the layering rule.

Utilisation

Every study calls buildNetwork first. The canvas renders synthetic-bus dots from getSyntheticBuses(); the grading chart's voltage-referral uses getComponentKv().

3 · Load flow — Newton–Raphson solver/loadFlow.ts

Purpose. Compute the steady-state bus voltages and the resulting branch and load currents/flows.

Method

Full Newton–Raphson power-flow with three bus types: one slack (the first grid source, fixed V∠0°), PV buses (additional grid sources — fixed |V|, scheduled P), and PQ buses (everything else). At each iteration the real/reactive power mismatch is formed and the Jacobian (∂P/∂θ, ∂P/∂V, ∂Q/∂θ, ∂Q/∂V) is solved via solveLinear for the voltage corrections.

Mismatch: ΔPᵢ = Pᵢ^sched − Σⱼ |Vᵢ||Vⱼ|(Gᵢⱼcosθᵢⱼ + Bᵢⱼsinθᵢⱼ) ΔQᵢ = Qᵢ^sched − Σⱼ |Vᵢ||Vⱼ|(Gᵢⱼsinθᵢⱼ − Bᵢⱼcosθᵢⱼ) Update: [Δθ, ΔV]ᵀ = J⁻¹ [ΔP, ΔQ]ᵀ until max|mismatch| < 1e-6

Convergence tolerance 1e-6, capped at 30 iterations. A divergence guard rejects any bus voltage leaving [0.5, 2.0] pu with a clear message. Per-load and per-motor currents are computed from the final bus voltages as I = S / (√3·V).

Implementing functions

  • solver/loadFlow.ts — runLoadFlow(net, opts?) → LoadFlowResult (buses, branches, loads, iterations, optional per-iteration history for the animation player).
  • store.ts — runLoadFlow() action (validates, builds the network, runs, sets runMode = "loadflow").

Utilisation

Toolbar → Run Load Flow. Bus voltages and branch currents appear on the canvas (edge labels, bus readouts) and in the results panel; an animation player can scrub the iteration history when Explain mode is on.

4 · Short circuit — IEC 60909 solver/shortCircuit.ts

Purpose. Compute the initial symmetrical three-phase fault current and peak current at a chosen bus, plus each source's contribution.

Method

A simplified IEC 60909 three-phase fault using the bus impedance matrix. Source impedances (grid sources, motors) are added to the Y-bus, which is inverted to Z. The fault is applied at the selected bus k:

I″ₖ (pu) = c / |Zₖₖ| (c = voltage factor, 1.10 max or 1.05 min) I″ₖ (kA) = I″ₖ(pu) × I_base,k X/R at fault = |Im Zₖₖ| / |Re Zₖₖ| κ = 1.02 + 0.98·e^(−3 / (X/R)) (IEC peak factor) i_p = κ · √2 · I″ₖ (peak short-circuit current)

Each source/motor contribution is recovered from the corresponding column of Z (current divider), and branch flows are decomposed so the canvas can show kA on each side of a transformer at its own voltage base.

Implementing functions

  • solver/shortCircuit.ts — runShortCircuit(net, faultBusIdx, cFactor) → ShortCircuitResult (ikSymKa, ipPeakKa, contributions, branchFlows).
  • store.ts — runShortCircuit(), setFaultBus(), setShortCircuitCFactor(), and getBusFaultLevels() (per-bus Ik″ for the grading chart).

Utilisation

Click a busbar → Run Short Circuit. The c-factor toggle (1.05 / 1.10) selects min/max fault current. Results show Ik″, i_p and contributions; the same engine feeds bus fault-level lines on the grading chart and the bolted current for arc flash.

Limitations. Three-phase (balanced, positive-sequence) faults only — no single-line-to-ground / sequence networks yet. The IEC 60909 Kt transformer correction factor and PV-bus Q-limits are not applied, so results are mildly optimistic.

5 · Motor starting solver/motorStart.ts

Purpose. Determine the voltage dip across the network when a chosen motor starts, and whether the motor terminal voltage is high enough to develop starting torque.

Method

Two load flows are run and differenced. Pre-start: all motors in normal PQ mode. During-start: the chosen motor is replaced by its locked-rotor impedance, modelled as a constant shunt admittance on its bus (so the drawn power scales with V², the physically correct stalled-rotor behaviour). The per-bus dip is pre-start pu − during-start pu.

The effective starting current depends on the start method:

MethodStarting current
DOL (direct-on-line)full locked-rotor current (LRC)
Star-deltaLRC / 3
Soft-startermin(LRC, 3.5 × FLC)
VFDmin(LRC, 1.1 × FLC)

Implementing functions

  • solver/motorStart.ts — runMotorStarting(project, motorId) → MotorStartingResult.
  • solver/network.ts — effectiveStartingCurrentRatio(method, lrc); buildNetwork(project, { startingMotorId }) injects the locked-rotor shunt.
  • store.ts — runMotorStarting(), setStartingMotor().

Utilisation

Click a motor → Run Motor Start. The results panel shows the motor's terminal voltage and starting current/kVA, and a per-bus voltage-dip table (tone-coded against typical 0.85/0.95 pu thresholds).

Limitation. Models the worst-instant inrush only — no run-up/acceleration-time integration or torque-speed curve, and one motor at a time.

6 · Overcurrent protection — IDMT src/idmt.ts

Purpose. Compute relay operate times and time–current curves for inverse-time and definite-time overcurrent protection, across multiple curve families and hardware models.

Method — curve families

IEC 60255-151: t = TMS · K / ((I/Is)^α − 1) SI K=0.14 α=0.02 · VI K=13.5 α=1 · EI K=80 α=2 · LTI K=120 α=1 IEEE C37.112: t = TDM · ( A / ((I/Is)^p − 1) + B ) MI 0.0515/0.114/0.02 · VI 19.61/0.491/2 · EI 28.2/0.1217/2 ABB RI: t = TMS / (0.339 − 0.236 / (I/Is)) Definite time: t = constant Pickup Is = plug_setting × CT primary rating

Multi-stage relays (low 3I>, high 3I>>, instantaneous 3I>>>) return the minimum operate time over enabled stages — the relay trips on whichever stage is fastest. The plotted composite curve is sampled with extra points straddling each stage pickup to render crisp vertical steps.

Relay hardware models

CT model

A current transformer is a property of a power wire (Connection.ct), not a placeable component. A relay references the wire it measures via RelayParams.measured_connection_id and trips its breaker over a dashed control wire. Pickup current is referred to the CT primary rating.

Implementing functions

  • src/idmt.ts — idmtOperateTime(relay, ct, I) (min over stages, dispatches IEC / IEEE / ABB-RI / DT); idmtCurvePoints(...) (plotted curve); primaryPickupA, relayHighestPickupA.
  • src/defaults.ts — RELAY_MODELS spec table (ranges + curve sets per model).
  • store.ts — resolveRelayLinks(), getRelayLinks(), getRelayFaultCurrents() (relay → fault current via the breaker's branch flow).

Utilisation

Relays are placed on the canvas and configured in the properties panel (model, curve, pickup, time, stages). Curves and operate-time markers appear on the Grading tab; the same operate-time function drives the arc-flash clearing time.

7 · Thermal overload protection (49) idmt.ts · protection/relay869Thermal.ts

Purpose. Model motor winding heating for thermal-overload protection — both as a static time–current limit curve and as a full time-domain thermal-capacity simulation.

7a · Static thermal curves (grading chart)

ABB REM615 (IEC 60255-149 replica, cold): t = τ · ln( I² / (I² − (k·Ib)²) ) GE 869 "Standard" overload curve (Cutoff), m = I / FLA: t = TDM · 2.2116623 / (0.02530337·(m−1)² + 0.05054758·(m−1)) held constant for m ≥ 8 (locked-rotor floor)

The GE coefficients are the exact values from the 869 manual and were verified against its Standard-Curve TD-Multiplier table (e.g. 2× = 29.16 s, 3× = 10.93 s, 5× = 3.64 s at TD = 1). Base current Ib defaults to the CT primary rating.

7b · GE 869 dynamic thermal model time-domain

A stateful simulation of Thermal Capacity Used (TCU, 0–100+%) implementing the 869 manual §9.2.1.2. Each step integrates heating or cooling; the relay trips at TCU = 100%.

Eq 1 (unbalance bias): Ieq = √( Iavg²·(1 + K·(I2/I1)²) ) Eq 2 (trip time): Standard curve above, or IEC 255-8 hot/cold with τ1 (stator) / τ2 (rotor) region selection Eq 3 (heating): ΔTCU = 100 · dt / t_trip Eq 4 (cooling): TCU → TCU_end + (TCU − TCU_end)·e^(−dt/τ_cool) TCU_end = (Ieq/OL)(1 − hot/cold)·100 running, 0 stopped

Also implemented: RTD-temperature bias (a parallel TCU estimate; the larger governs, cannot trip alone), trip/latch/alarm/block output logic, and power-loss memory (TCU persists or decays per the motor state at the outage). A voltage-dependent acceleration module exists behind a flag (unvalidated).

Implementing functions

  • src/idmt.ts — thermalCurvePoints(relay, ct, …) (static curve, dispatches ABB vs GE).
  • protection/relay869Thermal.ts — class Relay869ThermalModel (step(), equivalentCurrent(), tripTime(), applyControlPowerOutage()); geStandardTripTime() (single source of truth for the GE curve, reused by idmt).
  • protection/relay869Thermal.harness.ts — runnable validation harness (`npx tsx …`).
  • components/ThermalModeler.tsx — the interactive scenario modeler UI.

Utilisation

The static curve plots on the Grading tab (must sit above the motor-start curve, below damage limits). The dynamic model is driven from the GE-869 relay's properties panel → "Open thermal scenario modeler", which simulates TCU vs time over an editable current-vs-time scenario.

Validated. The harness reproduces the manual's trip-time table exactly and confirms cold-start floor settling, running-vs-stopped cooling constants, unbalance biasing (K=8) and power-loss memory. Not modelled: FlexCurves, voltage-dependent overload (exposed only experimentally), full RTD voting.

9 · Arc flash — IEEE 1584-2002 src/arcFlash.ts

Purpose. Compute the arc-flash incident energy, boundary and required PPE at a bus — the protection study's practical deliverable.

Method

Arcing current (lg = log₁₀): V < 1 kV: lg Ia = K + 0.662·lgIbf + 0.0966·V + 0.000526·G + 0.5588·V·lgIbf − 0.00304·G·lgIbf (K box −0.097 / open −0.153) V ≥ 1 kV: lg Ia = 0.00402 + 0.983·lgIbf Normalised energy: lg En = K1 + K2 + 1.081·lgIa + 0.0011·G Incident energy: E[cal/cm²] = Cf · En · (t / 0.2) · (610 / D)^x Arc-flash boundary: D_B = 610 · ( Cf·En·(t/0.2) / 1.2 )^(1/x)

The busbar carries an equipment class (switchgear, MCC/panelboard, cable, open-air) and grounded/ungrounded; the conductor gap G, distance exponent x and working distance D are then selected automatically from the bus's voltage band (≤1 kV / >1–5 kV / >5–15 kV) per IEEE 1584 Table 4 (resolveEquipment). PPE category follows NFPA 70E thresholds (1.2 / 4 / 8 / 25 / 40 cal/cm²).

Validity. The IEEE 1584-2002 empirical model is only valid 0.208–15 kV. Above 15 kV (e.g. 33 kV, 132 kV) the result is flagged out of range in the panel — the Lee theoretical-max-power method is the correct tool there and is not yet implemented.

Clearing time from protection: the engine derives the arc duration t from the fastest relay's operate time evaluated at the arcing current (each relay's fault current is scaled from the bolted bus current by the arcing/bolted ratio). Because arcing current is lower than bolted, the device clears slightly slower — the key arc-flash subtlety — and a flagged 2.0 s fallback is used if nothing operates.

Implementing functions

  • src/arcFlash.ts — arcingCurrentKa, incidentEnergyCal, arcFlashBoundaryMm, ppeRating, EQUIPMENT_CLASSES.
  • store.ts — runArcFlash() (short circuit → arcing current → clearing time → energy).

Utilisation

Click a busbar → Run Arc Flash. Results panel shows a cal/cm² badge (toned by PPE category), bolted/arcing current, clearing time and device, incident energy and boundary, with CSV export. Busbars carry an equipment-class and grounded/ungrounded setting.

Validated against the 480 V / 20 kA worked example (Ia = 11.22 kA). Not modelled: IEEE 1584-2018 (electrode configs, enclosure correction); whole-network table (selected bus only); fuse clearing times in the auto-derivation.

10 · Validation src/validation.ts

Purpose. Catch modelling problems before a run. Errors block a study; warnings inform but allow it.

Checks: missing/NaN parameters; required terminal connectivity; branch-neighbour rules (transformer / cable / switch / fuse may sit inline — a synthetic bus is created where needed); at least one grid source; transformer voltage-ratio vs connected-bus mismatch (warning); and protection completeness (relay needs a CT-equipped wire and a breaker).

Implementing functions

  • src/validation.ts — validateProject(project) → ValidationIssue[]; called by store.validate() before every run.

12 · Global limitations

  • Balanced positive-sequence only — no negative/zero-sequence networks, so no single-line-to-ground faults or ground (50N/51N) protection.
  • IEC 60909 simplifications — Kt transformer correction and PV-bus Q-limits not applied; results mildly optimistic.
  • Arc flash — IEEE 1584-2002 (not 2018); single selected bus; relay-only clearing-time derivation.
  • Motor starting — worst-instant inrush; no run-up integration or torque-speed modelling; single motor.
  • Fuse / cable / transformer curves — representative educational fits, not manufacturer data.
  • Numerical — absolute (not relative) pivot tolerance in the linear solver; no automated solver test suite yet.
  • This is a learning / engineering exploration tool — verify against vendor data and the governing standards before using results for compliance work.
